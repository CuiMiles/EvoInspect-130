# 导师最终拍板：立即恢复实验，主攻一条真正可获奖的路线

我已经按你们提交的导师咨询材料逐项审阅。当前项目处于 **G1：强基线已经建立，但核心创新还没有验证成功，并且新实验处于暂停状态**。

现在不需要继续等待意见。我的决定是：

> **解除实验暂停。停止继续修补 HeteroMemory、GuardedFusion 和 MaskedPrototype。**
> **主创新转为：风险校准的硬预算高分辨率复检路由。**
> 英文暂定：**Risk-Calibrated Budgeted Refinement，RCBR**。
> 中文可包装为：**面向严格低误报工业质检的风险校准预算路由方法**。

最终作品的主叙事不是“又一个异常检测模型”，而是：

> **在只有100张正常图和30张缺陷图的条件下，针对2500×2500工业图像，在RTX 2060级硬件上，以严格低误报率完成小缺陷实时定位，并支持反馈、验证和回滚。**

这条路线最符合你们当前已有证据，也最容易转化为评委能理解的竞争优势。

---

## 一、先纠正一个最重要的方向问题

你们原来提出的普通 BudgetRouter：

* 低分辨率全图检测；
* 选出可疑区域；
* 对局部区域做高分辨率复检；

**这个思想单独拿出来已经不够创新。**

HiAD 已经使用高低分辨率双分支、检测器池和自适应分配来兼顾高分辨率异常检测与计算成本；3CAD 的 CFRG 已采用 coarse-to-fine 方式处理小缺陷；CPR 使用级联 patch 检索；Tiled Ensemble 也已经用分块集成解决高分辨率工业异常检测问题。([arXiv][1])

所以不能在答辩中说：

> “我们首次提出粗到细的工业异常检测。”

会被懂行的评委直接问穿。

正确包装是：

> **已有方法主要解决高分辨率计算问题，我们进一步面向工业现场的严格低误报约束，把正常样本风险校准、缺陷样本收益估计、真实硬件时延成本和确定性安全回退统一到同一个路由决策中。**

这是**赛题约束驱动的组合创新**。不必宣称理论首创，但只要做出稳定结果，完全足以成为竞赛核心创新。

# 二、为什么这条路线是当前唯一正确主线

你们现在的 PatchCore 基线已经相当强：

* Overall F1：0.9224；
* Image AUROC：0.9817；
* Unseen F1：0.8715；
* AUPRO@0.30：0.9342。

继续尝试普通分数融合，很难再获得稳定收益。

但严格低误报定位仍然存在明显缺口：

* AUPRO@0.05：0.7241；
* 1%背景误报率下的 PRO：0.5764；
* wood、capsule、transistor、metal_nut、grid 明显较弱。

这说明当前真正的问题不是：

> “图片是否能判断为异常？”

而是：

> **在不能乱报的工业条件下，能否准确找到微小异常区域？**

这恰好同时连接了四个官方要求：

1. 2500×2500高分辨率；
2. GTX 2060级实时性能；
3. 小样本适配；
4. 工业场景不能大量误报。

你们已经尝试的 HeteroMemory、GuardedFusion、MaskedPrototype 和简单浅层特征路线，要么使 unseen 性能下降，要么全部回退到 PatchCore，要么明显降低 F1，已经没有继续投入的依据。

# 三、最终主算法：RCBR

## 3.1 总体结构

最终在线模型不应继续以 WideResNet-50 PatchCore 为唯一运行核心。

正确结构是：

```text
PatchCore
└── 强精度基线、离线教师、研究对照
    不作为最终RTX 2060实时主模型

EfficientAD-S或同级轻量学生
└── 最终全图快速检测器
    ↓
风险校准与候选区域生成
    ↓
硬件预算路由
    ↓
共享模型高分辨率局部复检
    ↓
安全融合与确定性回退
```

EfficientAD 本身就是针对毫秒级工业异常检测设计的轻量学生—教师方法，并且包含用于全局逻辑异常的分支，因此比 PatchCore 更适合最终实时运行图。([arXiv][2])

PatchCore仍然保留，而且非常重要：

* 作为正式强基线；
* 作为精度上界参考；
* 可以离线生成教师特征；
* 可以辅助分析轻量模型漏检区域；
* 不能把它的3090结果冒充最终2060结果。

---

## 3.2 模块一：正常风险校准

官方给出的100张正常图，不应全部只用来建立正常记忆库。

建议：

* 80张用于正常模型或记忆构建；
* 20张用于风险校准；
* 或使用5折 cross-conformal/cross-fitting，让100张样本都能参与。

对每个空间区域、组件区域或外观簇，建立正常异常分数分布：

```text
当前区域得分
↓
在正常校准样本中的分位数
↓
局部误报风险 / calibrated p-value
```

这样 wood、grid 等正常纹理变化较大的区域，不会因为原始异常分数稍高就被大量误报。

需要特别说明：

* 不应宣称获得绝对的像素级统计保证；
* 应表述为“正常样本驱动的区域条件风险校准”；
* 如果使用 conformal prediction，必须报告覆盖率和校准偏差。

---

## 3.3 模块二：ROI候选生成

候选区域不能只来自低分辨率异常热图，否则低分辨率已经漏掉的小缺陷永远不会被复检。

候选信号至少包括：

1. **校准后异常风险**；
2. **多尺度预测不一致性**；
3. **轻量边缘、纹理或高频显著性**；
4. **组件和空间位置先验**；
5. **正常样本中罕见但未达到报警阈值的区域**。

每个ROI记录：

```text
位置
尺寸
异常风险
不确定性
预计复检收益
预计运行成本
被选中的原因
```

这部分既服务算法，也服务演示和可解释性。

---

## 3.4 模块三：收益—成本路由

对每个候选ROI计算：

[
U_i = \widehat{P}(\text{复检后发现真实缺陷})
-\lambda \widehat{P}(\text{复检后产生误报})
]

同时通过真实硬件测速表获得成本：

[
C_i = \text{该尺寸ROI在当前设备上的预测时延}
]

路由问题变成：

[
\max \sum_i U_i x_i
]

约束：

[
\sum_i C_i x_i \leq B,\quad x_i\in{0,1}
]

其中 (B) 是剩余时延预算。

第一版无需强化学习，也不需要复杂神经路由器。优先使用：

* 逻辑回归或轻量GBDT估计收益；
* 贪心收益/成本比；
* 小规模0/1 knapsack；
* 非极大抑制去除重叠ROI；
* 固定最大ROI数量。

这样更容易解释、调试和部署。

### 固定硬限制

建议第一版直接写死：

* 最大ROI数量：4；
* 平均复检面积：不超过原图15%；
* p95复检面积：不超过25%；
* 最大复检面积：不超过35%；
* 每张图必须存在确定性最坏时延上限；
* 预算耗尽后禁止继续增加ROI。

---

## 3.5 模块四：共享模型局部复检

局部复检不要再增加一个重型模型。

建议：

* 全图和ROI共享同一个轻量异常检测网络；
* 全图以低分辨率运行；
* ROI以更高像素密度运行；
* 使用同一套权重；
* 可使用不同的正常记忆或校准参数；
* 最终在线神经网络主体数量保持在官方限制以内。

不要优先使用：

* 第二个WideResNet-50；
* DINOv2大模型在线推理；
* 扩散模型在线推理；
* 大型分割模型；
* VLM在线解释。

这些可以做离线教师，但不应进入最终实时图。

---

## 3.6 模块五：安全融合

局部复检只能在满足校准条件时修改最终热力图。

建议采用单调安全规则：

```text
如果局部复检证据不足：
    保留全局结果

如果局部复检证据充足：
    只更新对应ROI

如果路由或模型异常：
    确定性回退到全局输出
```

同时保留：

* 原始全局结果；
* 局部复检结果；
* 融合结果；
* 被选ROI；
* 触发原因；
* 所用预算；
* 是否发生回退。

这会成为答辩中非常好展示的一部分。

# 四、30张缺陷样本怎么使用

你们之前最大的问题，是把少量seen defects直接转化成监督分数，导致对seen有利、对unseen退化。

现在重新规定：

## 第一优先级

30张缺陷用于：

* 估计不同ROI特征下“复检是否值得”；
* 校准局部复检阈值；
* 选择ROI尺寸和复检尺度；
* 评估seen/unseen之间的风险；
* 训练轻量路由收益模型；
* 错误切片分析。

## 第二优先级

如果提供mask，可以用于：

* 监督ROI覆盖率；
* 局部阈值校准；
* 判断小缺陷是否被完整覆盖。

如果只有图像级标签，也必须能够正常运行。

## 暂时禁止

在主创新验证前，不允许：

* 用30张缺陷大幅微调主干网络；
* 把缺陷原型直接混进正常PatchCore记忆库；
* 根据确认集结果反复调融合权重；
* 只优化seen F1而忽略unseen F1；
* 使用确认集mask训练局部分割头。

AHL已经表明，少量已知异常的价值在于帮助模型理解异质异常分布，而不是把问题退化成普通闭集分类。([arXiv][3])

## AD-P0-02：是否必须总体F1超过PatchCore

**不要求所有指标超过PatchCore，接受明确的质量—时延 Pareto 改善。**

但必须满足质量保护线：

| 指标          |       最大允许下降 |
| ----------- | -----------: |
| Overall F1  | 绝对下降不超过0.003 |
| Unseen F1   | 绝对下降不超过0.005 |
| Image AUROC | 绝对下降不超过0.002 |
| AUPRO@0.30  | 绝对下降不超过0.005 |

同时至少满足：

| 主要收益               |             全15类开发集门槛 |
| ------------------ | --------------------: |
| AUPRO@0.05         | 相对PatchCore绝对提高≥0.015 |
| PRO@1% FPR         |            绝对提高≥0.020 |
| Small-region AUPRO |            绝对提高≥0.010 |
| 2060端到端p95         |    目标≤180ms，硬门槛<200ms |

如果总体F1持平，但严格低误报定位明显改善，且速度满足要求，这是完全成立的竞赛创新。

## AD-P0-04：开发和确认协议

正式批准：

* seeds 130–132：开发、调参和消融；
* seeds 133–137：只作为已经发生的诊断证据，不再用于选择模型；
* seeds 138–142：最终冻结确认，只能运行一次。

因为新方向受到133–137错误切片启发，最终还必须增加一个独立外部数据集，避免只针对同一批MVTec图像优化。

## AD-P0-05：先三类还是全15类

先做四类，不是三类：

* wood：最弱低FPR和小区域；
* capsule：严格低FPR弱；
* transistor：复杂结构；
* hazelnut或bottle：强性能对照类，防止只挑弱类产生选择偏差。

顺序：

1. 四类 × seed 130功能smoke；
2. 四类 × seeds 130–132最小消融；
3. 通过门槛后才做15类 × 3开发seed；
4. 冻结后做15类 × 5确认seed。

## AD-P0-10：视频和逻辑异常

视频和逻辑异常必须完成，但不作为第二个论文级研究主题。

最低完成：

* 视频读取和流式推理；
* 异常分数时序平滑；
* 连续帧事件合并；
* 组件状态记录；
* 有限状态机检测步骤跳过、重复和顺序错误；
* 事件级precision、recall、F1；
* 可解释事件输出。

MVTec LOCO类研究表明，逻辑异常与局部结构异常本身是不同问题，需要全局组件关系或组合信息；因此简单逐帧热力图不能冒充完整逻辑异常检测。([arXiv][5])

# 六、论文和竞赛表述决定

## 负结果

HeteroMemory和GuardedFusion负结果保留，但只占：

* 一张表；
* 一段分析；
* 一张答辩备份页。

包装方式：

> “直接利用30张缺陷进行监督融合会过拟合已知异常并损害未知异常，因此我们转向将缺陷样本用于收益校准，而不是主干表征微调。”

这是很好的研究动机，但不是正创新。

---

## 统计标准

如果要写“定位准确率显著提升”：

* paired bootstrap 95% CI必须整体大于0。

如果CI跨0：

* 不得写显著优于；
* 可写均值改善；
* 如果质量满足非劣效界限、时延显著降低，可以保留为Pareto贡献。

质量非劣效界限：

* Overall F1：-0.003；
* Unseen F1：-0.005；
* Image AUROC：-0.002。

---

## 宏平均和微平均

两者都报告：

* 宏平均：论文和研究主指标；
* 微平均：接近可能的官方图片级评测；
* 每类别结果：放附录；
* 不允许只报告表现最好的类别。

---

## 缺陷区域尺寸

停止使用每个任务内部q25/q75作为最终定义，因为跨数据集无法比较。

统一使用缺陷区域占原图面积比例：

| 类别    |    面积占比 |
| ----- | ------: |
| Tiny  |   ≤0.1% |
| Small | 0.1%–1% |
| Large |     >1% |

另外保留原分位数结果作为补充，不作为主要结论。

---

## 新数据集优先级

### 第一优先：MVTec AD 2

它直接包含：

* 高分辨率图像；
* 极小缺陷；
* 暗场、背光；
* 透明和重叠物体；
* 光照变化；
* 公开评测服务器。

这最能支撑你们的高分辨率、小缺陷和环境漂移主张。([arXiv][6])

### 第二优先：MVTec LOCO AD

用于逻辑、数量、组件组合和结构异常。

### 第三优先：3CAD

它来源于真实3C产品生产线，包含大量高分辨率图像和多尺度异常，对华为手机组装类场景非常相关；但其自身已经提供coarse-to-fine基线，必须明确差异。([arXiv][7])

### 第四优先：DAGM 2007

只作为传统纹理跨域补充，不要把大量时间投入其中。

## 持续学习深度

本届作品先完成“可信闭环”，不做完整持续学习论文：

1. 操作员提交误报或漏报；
2. 更新阈值、校准器、ROI收益或轻量原型；
3. 生成候选版本；
4. 在历史回放集和新样本上测试；
5. 通过门槛才进入影子版本；
