# 《智检演化130》旁白稿（候选，不是提交物）

用途：为现有 `submission/final/Cuisine_智检演化130_项目视频.mp4` 录制真人旁白。画面不重剪，旁白按时间段对齐；录音完成后再由参赛者试听、确认数字和音画同步，不能把本文件视为已完成音轨。

录音建议：安静房间，距麦克风 15–20 cm，44.1/48 kHz，正常语速；不加入未经授权的背景音乐。开头保留约 0.3 秒静音，录完完整听一次。

## 时间轴

**0–10 秒**  智检演化130面向工业新产品上线，用100张正常与30张缺陷样本完成快速适配。

**10–20 秒**  我们同时解决四个问题：外观检测精度、低端GPU实时性、装配逻辑异常，以及人工反馈可能造成的历史能力退化。

**20–35 秒**  系统由统一推理接口连接四条支路。PatchCore负责精度模式，EfficientAD-M负责实时模式，视频分支识别缺件、重复和换序，GuardedAdapt负责候选发布、门禁和回滚。

**35–55 秒**  图像输入后，系统输出异常分数、热力区域、置信度、模型版本和分阶段时延。PatchCore在MVTec AD十五类五种子评测中，Overall F1达到0.9224，图像AUROC达到0.9817，作为精度优先模式。

**55–73 秒**  实时模式部署在真实六GB GTX2060上。对2500乘2500输入，ONNX FP16模型前向p95为19.4毫秒，包含解码、预处理、后处理和序列化的端到端p95为166.2毫秒。

**73–79 秒**  视频侧以杯子、水瓶、鼠标为标准工序，并输出装配事件时间线。

**79–107 秒**  正常片段依次完成三个步骤；缺件片段在流程结束时报告missing；重复片段在水瓶再次出现时报告repeat。五段实拍视频共十九个真值事件，匹配十八个，事件F1为0.9474。

**107–115 秒**  核心创新GuardedAdapt不会在收到反馈后直接改写线上模型，而是先生成有界候选，再检查反馈收益和历史锚点。

**115–125 秒**  当候选改善当前反馈，同时不破坏历史能力时，新版本才被接受，并记录完整的版本变化。

**125–135 秒**  当候选造成历史能力退化时，系统拒绝发布并恢复Champion。十一项拒绝更新全部精确回滚。

**135–149 秒**  离线回放中，无约束更新的有害率为9.33%，GuardedAdapt降至2.67%，相对减少71.4%，同时保持85.33%的更新接受率。

**149–159 秒**  因此，智检演化130不是一个单一检测模型，而是一套兼顾精度、实时、装配逻辑和反馈安全的离线AOI闭环。

## 合成命令（获得录音后）

```bash
ffmpeg -y \
  -i submission/final/Cuisine_智检演化130_项目视频.mp4 \
  -i narration.wav \
  -filter_complex "[1:a]loudnorm=I=-16:TP=-1.5:LRA=7,apad[a]" \
  -map 0:v:0 -map "[a]" \
  -c:v libx264 -preset medium -crf 18 \
  -pix_fmt yuv420p -movflags +faststart \
  -c:a aac -b:a 160k -ar 48000 \
  -shortest \
  submission/drafts/project_video_narrated.mp4
```

合成后用 `ffprobe` 确认存在视频轨和 AAC 音频轨，并完整试听；真人录音失真或数字读错时，保留静音保底版。
